# 学习问答（sqs:learn）

## 参数

`$ARGUMENTS` 形如 `<模式> <对象>`，顺序不限（`video-editing是什么` 等同 `是什么 video-editing`）。

- 模式只接受四个词：`是什么`、`怎么用`、`原理`、`讨论`。
- `讨论` 模式：以 `/sqs:learn 讨论 <对象>` 进入，进入后整场会话都是讨论。
- 缺模式或缺对象时，只用一句话问清缺的那项，然后停止。

## 执行方式：两种模式

先判断模式，两条路互斥。

### 问答模式（`是什么` / `怎么用` / `原理`）：必须走子代理

派生一个**普通子代理（general-purpose，不是 fork）**，任务描述里只放模式、对象和「回答规范」「笔记」「子代理任务说明」三节。不要把主会话的对话内容带进去。主会话不自己调研、不自己展开。

主会话收到子代理结果后：

- 简单结论：把子代理给的几行原样转述，不加开场白、不加总结、不问"要不要继续"。
- 复杂结论：只说一句话说明写进了哪个文件，最多再附三行要点。

### 讨论模式（`讨论`）：留在主会话

**不派生任何子代理**，从头到尾都由主会话自己回答。

用户会为讨论单独开一个新会话，因此进入讨论后，整场会话都按讨论模式处理：后续追问、临时换对象、来回澄清，都由主会话承接，不再新开子代理，也不再套用问答模式的规则。

## 回答规范（四种模式通用）

### 1. 只答被问的那一层

- `是什么`：一句话说清它是什么、解决什么问题。最多再补一句它在当前任务里的位置，总共不超过 3 行。不展开链条、不列步骤、不做横向类比。
- `怎么用`：给出用法；处在流程中时按第 2 节的格式展开步骤。不展开原理。
- `原理`：内部机制与设计原因。不重复"是什么"和"怎么用"。
- `讨论`：用户问到哪一层就答哪一层，没问的层不主动补。

只给回答这一层必需的信息，不补充没被问到的背景、类比或横向关联。不主动往下推，不问"要不要继续讲"。

### 2. 给链条

`是什么` 最多给一行流程定位，没有就不写。

问的是用法时才展开步骤，把它放进流程中定位，而不是罗列功能。格式：

```
流程定位：<上游> → **<本对象>** → <下游>

第 1 步 <名称>：<怎么用> → <产出什么>
第 2 步 <名称>：<怎么用> → <产出什么>
```

几行说完。没有明确上下游时省略这一段，不要硬凑。

## 讨论模式规范

### 1. 结合上文回答

必须使用会话里已经出现的讨论内容：前面的回答、用户的纠正、双方达成的口径。第二问要能接上第一问，而不是重新开始——讨论的价值就在这里。

### 2. 必须短

- 用户问什么就答什么，不允许展开、不允许反问（第 3 节写文档前的确认除外）。允许顺着上一轮往下走。
- **一次只讲一段话能说清的量**：最好能在 10 行内讲完，实在不行允许超出。不要一次输出大段教程、长清单或完整文章——看不过来等于没回答。
- **准确优先于篇幅**：不确定就说不确定，不要为了显得完整而补内容。
- 用户提出的前提如果有误，直接指出，不要顺着说。

### 3. 写文档要经用户确认

讨论模式下不自行判断后就落盘。

- 当讨论积累到值得留存，或用户主动要求时，问一句：要不要写进 `learn-docs/<知识点>.md`？
- 用户确认后才写；用户主动说"写文档"时直接写，不再多问。
- 没确认前，文档一个字都不写。

笔记规则见「笔记」一节。

### 4. 会话边界

用户换会话即重新开始。不跨会话传递上下文，也不假设别的会话聊过什么。

## 笔记

项目根目录 `learn-docs/`，不存在就创建。

- 文件：`learn-docs/<知识点>.md`。写入前先检查是否已有同知识点的文件，有就补充，不新建。
- 结构：

```markdown
# <知识点>

一句话定位：...

最后更新：YYYY-MM-DD

## 已讲到的层

### 是什么

...

### 怎么用

...

### 原理

...

## 链条

- 上游：...
- 本对象：...
- 下游：...

## 相关

- ...
```

只记录这次实际讲到的层，已有的层保留不覆盖。

- 讨论中归不进「是什么 / 怎么用 / 原理」三层的结论，记在 `## 讨论要点` 小节下，每条一句，只记结论和适用条件。
- 索引：`learn-docs/README.md`，一行一个知识点：`- [<知识点>](<文件>) — 一句话`。新建文件时追加，已有条目就更新那一行。

## 子代理任务说明

回答规范与笔记规则见上文，本节只列子代理的额外约定。

### 1. 不依赖会话上下文

你只拿到模式、对象和本说明，看不到用户当前的对话。不要猜测或假设用户正在做什么。

用户没有在问题里给出场景时，按通用解释回答，必要时注明这是通用解释；用户在对象后面补了场景或约束时，按那个场景裁剪，只讲相关的那一片。

### 2. 简单 / 复杂

- 简单：结论 5 行内说得完，或只涉及一个概念 → 直接返回，不写文件。
- 复杂：需要多级链条、代码示例，或涉及两个以上概念 → 写入笔记后返回。

### 3. 返回给主会话

- 简单：只回最终答案的几行。
- 复杂：回一行 `已写入 learn-docs/<文件>`，后附三行以内要点。

不返回调研过程，不贴工具输出。

## 不做的

- 不自动触发；普通问答里不套用本规范。
- 问答模式下不把问答过程留在主会话；讨论模式反之，讨论全过程就在主会话。
- **讨论模式下不派生任何子代理。**
- **讨论模式下不写长文**：一次只讲一段能看清的量，把展开留给追问。
- 不写 `learn-docs/` 以外的位置。
